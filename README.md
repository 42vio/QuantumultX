# QuantumultX

## 顺丰速运签到

`scripts/sfexpress.cookie.js` 分别保存 App 的 `universalSign` 原生认证请求和签到页 Web 会话，数据仅保存在 Quantumult X 本地偏好设置。`scripts/sfexpress.js` 优先重放该账号的原生认证请求，获取新的 `sign`，通过 `shareRedirect` 换取新的 Cookie，再查询/执行签到和领取每日任务积分，最后合并所有账号的通知。不同账号使用独立 Cookie；换得的账号标识不匹配时停止该账号操作。未采集 App 请求的旧账号暂时沿用原来的 Web 会话。

更新重写及任务脚本后，使用支持 `auto-cookie: false` 的 Quantumult X（build 934+），依次登录每个账号并打开积分签到页，确认出现“App 认证请求已保存”和“会话已更新”通知。手动运行一次后，关闭顺丰 App，超过 15 分钟再次运行，并在次日复测。**当前仅完成静态分析和本地模拟测试，未验证 iPhone 原生请求签名的重放有效期；不能保证已解决长期失效。** 若提示“App 换取会话失败”，需继续分析原生签名/登录态，反复保存 Web Cookie 无法解决。多账号登录互踢也可能使旧账号的 App 登录态失效。分析记录见 [docs/sfexpress-auth-analysis.md](docs/sfexpress-auth-analysis.md)。

每日任务恢复原执行流程：状态 `1` 直接领取积分，状态 `2` 先调用 `finishTask` 再尝试领取；服务端仍返回“任务未完成”的项目逐项记录失败，不计为成功。原生换票被拒绝时，如果存在账号标识匹配的已保存 Web 会话，会先查询今日签到状态验证该会话，通过后继续签到和任务，并在通知中注明使用了旧 Web 会话；此回退不能延长已失效 Cookie 的寿命。账号不匹配或异常登录跳转不会触发回退。换票错误保留安全错误码和原因类别。

当前官方签到网页查询任务和领奖使用同一个网页 `myPoints_UUID`，并非 App 请求头的 `deviceid`。请同时更新重写和脚本，重新打开积分签到页，收到“每日任务设备信息已保存”后再运行。采集到的任务 `deviceId` / `channelType` 按账号独立保存；查询使用这两个字段，领奖使用同一 `deviceId`，完成任务仍按原脚本只发送 `taskCode`。未采集时沿用原作者脚本的旧参数，不用 App 设备 ID 顶替，也不阻断签到。当前只验证了官方前端参数与本地模拟逻辑；这些差异是否为真机零领取的根因仍待确认。


## 下班打卡提醒（Quantumult X）

`scripts/attendance-qx.js` 同时负责保存 App 的 `GetAttendData` 查询请求，以及在 17:20 从同一台手机重放该请求、计算下班时间并通知。提醒时间取“上班打卡后 9 小时”和当天 17:30 中较晚的时间。查询请求只保存在 QX 本地偏好设置中；仓库脚本不包含账号、会话或设备标识。`QuantumultX_Cookie.qxrewrite` 已包含该 App 的重写和 MitM 域名，`TaskGallery.json` 已加入 17:20 任务。推送后，在 iPhone QX 更新这两个现有订阅。

手机时区设为中国标准时间，开启 QX 隧道、MitM 和通知权限。首次使用时打开考勤 App 的当日考勤页，收到“考勤重写成功：已保存考勤查询请求”通知后，在 QX 任务列表手动运行该任务，确认时间与 App 一致。后续任务每天自动查询；若服务端使保存的会话失效，重新打开当日考勤页即可刷新。若开启该域名的 MitM 后 App 卡在连接中，先移除新规则，保持 App 可用。脚本不执行打卡。
